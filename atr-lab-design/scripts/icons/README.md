# ATR icon pipeline

Regenerates, extends and rebuilds the ATR Lab icon set in `atr-lab-design/assets/icons/`.
Every icon is generated by Codex image generation as **solid black on flat chroma green**, keyed to
an alpha master, normalised, then recolored, badged and traced programmatically. Color never comes
from the generator, so every output is palette-exact (`#003976` navy, `#EFAB00` gold, white, `#1B2533` ink).

```
generate.py  ->  raw PNG (black glyph on #00FF00)        a working folder (the ATR build repo: build/icons-src/)
slice_sheet.py ->  one cell PNG per icon (sheets only)     build/icons-src/<dir>/cells/
chroma_key.py  ->  alpha master, 512 px, 12 % padding     assets/icons/masters/<name>-mask.png
recolor.py     ->  navy / gold / white / ink PNG           assets/icons/png/<name>-<color>.png
badge.py       ->  circle badges                           assets/icons/badges/<name>-badge-{navy,gold}.png
trace.py       ->  single-color polygon SVG                assets/icons/svg/<name>.svg
build_set.py   ->  runs key + recolor + badge + trace for every icon in a selection file
qa_sheets.py   ->  contact sheets + weights.csv            build/qa/icons/
make_readme.py ->  assets/icons/README.md from icons.json + build-report.json (numbers computed, never typed)
```

Python: a virtual environment with `scripts/requirements.txt` installed (Pillow, numpy, scipy,
scikit-image, vtracer; setup in `scripts/README.md`). SVG round-trip QA uses `rsvg-convert` (librsvg) on
`PATH`; MacPorts' `/opt/local/bin/rsvg-convert` is also tried. The scripts that import their siblings set
`sys.dont_write_bytecode`, so no `__pycache__` lands in the skill; if you import a module from your own code,
set `PYTHONDONTWRITEBYTECODE=1`. Paths under `build/` (raw generations, `selection.json`, `prompts.json`,
QA sheets) are records in the ATR build repository, next to the skill folder; they are not needed to run the
scripts.

## 1. The style, in one prompt

`icons.json` holds the shared **style block**, the **reference note** and one **subject** line per
icon (plus optional `min_px`, the icon's minimum size, and `"fill": "solid"` for the few conventional
solid pictograms). A single-icon prompt is:

```
Icon subject: <subject>. <style block> <reference note>
```

Style block (verbatim; keep it, it is what makes the set look like one family):

> Style: a single flat geometric monoline pictogram with one uniform heavy stroke weight (each
> stroke about 8 percent of the icon width), built only from straight line segments meeting at
> 45-degree and 60-degree angles, with chamfered (beveled, cut-off) corners and no rounded corners
> and no curves, minimal detail so it stays readable at 24 pixels. Colors: the glyph is solid pure
> black (#000000) and the ENTIRE background is one perfectly flat, uniform chroma-key green
> (#00FF00) that fills the whole square canvas edge to edge. Absolutely no shading, no gradients,
> no shadows, no outlines, no highlights, no texture, no text, no letters, no numbers, no
> watermark, no border, no frame, no ground line, no extra background shapes. The subject is
> centered on a square canvas with about 12 percent empty green margin on every side.

Reference note (appended whenever a reference image is attached):

> The attached reference image is a sibling icon from the same icon set: match its stroke
> thickness, chamfered corner style, angle vocabulary and overall visual density exactly, but do
> NOT copy its subject; draw only the subject described here.

Subject-writing rules that worked:

- Name the viewpoint ("seen from the side") and build the object from named primitives (octagon
  head, hexagonal nodes, diamond rotors, chevron arms).
- **Fill logic**: the set is outline forms with hollow interiors; ask for "a heavy hollow outline
  as thick as the reference icon's arms" for bodies, plates, bases and dials, and reserve "solid"
  for small details (nodes, buttons, markers, a sensor pad). Only conventional solid pictograms
  (map pin, gear, people, medal, handshake) are filled silhouettes; flag those with
  `"fill": "solid"` in `icons.json` so the QA gate exempts them.
- Forbid what the model thins out: "no thin lines", "no dashed lines", "connection bars drawn with
  exactly the same heavy stroke thickness", "struts as thick as the reference icon's arms". Even
  so, connecting bars and outlines often come out thinner than solid parts; that is what the
  `min_stroke` normaliser in `selection.json` is for (section 3d).
- Keep compound subjects to two figures and one connector, and say the size of each part ("each
  about 40 percent of the icon width") so the pair fills the canvas.
- Never ask for letters, digits or a dollar sign; the style block already bans text.

## 2. The reference-image trick (style anchor)

The set is locked to one anchor: `scripts/icons/anchor.png` (a copy of the build repo's
`build/icons-src/anchor/anchor.png` = `gripper-b.png`, the chevron gripper). It was chosen from four
candidates (`build/qa/icons/anchor-candidates.png`) and is passed to **every** later generation with
`--ref` (`generate.py` uses it by default; `--no-ref` turns it off), so the model matches its stroke
weight, chamfers and density. `codex_image.sh` accepts any number of reference images after the prompt.

Sheets vs singles: we tested both (`build/qa/icons/test-sheet-vs-singles.png`). **3 x 3 sheets are
more consistent** (stroke 6.6-9.4 % of the canvas vs 4.7-9.4 % for singles, and simpler, more
legible forms because the model draws nine siblings at once), so sheets are the default for a
batch (`--sheet 3`). Cells are ~400 px in a 1254 px sheet, which is plenty for a 512 px master and
for tracing. Generate two or three variants of each sheet (`--tag A-v1`, `A-v2`, ...) and pick the
best cell per icon; whole sheets occasionally come out in a thin outline style (sheet A-v2 did) and
are simply discarded. Singles (1254 px) are the right tool for one-off fixes and additions: the fix
rounds (`build/icons-src/fix/`, tags `fix-v1..v6`, `S-v1/S-v2`) were generated that way from
alternate manifests (`fix/alt-*.json`, written by `fix/make_alt_manifests.py`) with `--manifest`.

## 3. Commands

```bash
# Run from the skill root (atr-lab-design/). SRC is a working folder for raw generations outside the skill;
# in the ATR build repo it is ../build/icons-src, which also holds selection.json and prompts.json.
PY=.venv/bin/python; S=scripts/icons; SRC=../build/icons-src
PROMPTS=$SRC/prompts.json    # the canonical, append-only prompts manifest

# a) one new icon: add it to icons.json (meaning, keywords, subject), then
#    (--ref defaults to $S/anchor.png and --codex to scripts/codex_image.sh)
$PY $S/generate.py --out $SRC/new --names new-icon --tag v1 --prompts $PROMPTS
$PY $S/chroma_key.py $SRC/new/new-icon-v1.png $SRC/new/new-icon-mask.png --report

# b) a sheet of nine (put weak subjects in twice if you want two candidates)
$PY $S/generate.py --out $SRC/sheets --names a,b,c,d,e,f,g,h,i --sheet 3 --tag F-v1 --prompts $PROMPTS
$PY $S/slice_sheet.py $SRC/sheets/sheet-01-F-v1.png $SRC/sheets/cells --names a,b,c,d,e,f,g,h,i --tag F-v1

# c) key + inspect candidates (chroma_key warns if you feed it an unsliced sheet; --strict refuses)
$PY $S/chroma_key.py --batch $SRC/sheets/cells $SRC/sheets/masks --report > $SRC/sheets/masks-report.json
$PY $S/qa_sheets.py $SRC/sheets/masks $SRC/sheets/compare     # contact sheets of every candidate mask

# d) record the winners in selection.json, then rebuild
#    {"name": "sheets/cells/name-F-v1.png"}                              plain
#    {"name": {"src": "fix/name-fix-v5.png", "min_stroke": 0.065}}     with the stroke normaliser
$PY $S/build_set.py --selection $SRC/selection.json --out assets/icons [--only name]
$PY $S/qa_sheets.py assets/icons/masters ../build/qa/icons    # label font: the skill's Source Sans 3
#    look at size-24px.png / size-32px.png and set "min_px" in icons.json for icons that need more than 24 px
$PY $S/make_readme.py            # refreshes assets/icons/README.md (manifest table; all numbers computed;
                                 # --selection $SRC/selection.json, else the src recorded in build-report.json)
$PY $SRC/rebuild_prompts.py      # build repo only: merges prompts.json, keeps every record, refreshes selection
```

`generate.py` runs up to `--jobs 6` Codex calls concurrently (each 45-90 s) and appends every call
to the prompts manifest under a file lock (POSIX; on Windows run one `generate.py` at a time). Always
pass `--prompts $SRC/prompts.json` so the record lands in the canonical file (a run without it writes a
list-form `<out>/prompts.json`, which `rebuild_prompts.py` folds in later). `prompts.json` is
**append-only**: `rebuild_prompts.py` unions the existing records, every list-form manifest under
`build/icons-src` and the reconstructable plan by `(file, tag)`, writes `prompts.json.bak` first and
refuses to drop anything. Sheet records carry a `cells` map (icon -> sliced cell file) so a selected
cell can be traced back to its Codex call.

`codex_image.sh` usage, for a manual call:

```bash
scripts/codex_image.sh out.png "Icon subject: ... . <style block> <reference note>" scripts/icons/anchor.png
```

## 4. Chroma key details (`chroma_key.py`)

1. Measure the real background from the outer 2 % border (median), so slight green drift is fine.
2. HSV distance per pixel: hue difference (deg / `--hue-tol 40`), saturation drop and value drop
   relative to the background; the max of the three is the distance.
3. Soft alpha = distance / `--soft 0.35`, then a keyer clip: below `--clip-lo 0.18` -> 0 (noise
   floor), above `--clip-hi 0.85` -> 1, linear between (edges stay anti-aliased).
4. Despill: un-mix the background out of edge pixels (`fg = (px - (1-a) bg) / a`). The master is
   forced black unless `--keep-color`.
5. Specks below `--min-speck 0.0004` of the area are removed (soft noise counts).
   Enclosed green regions stay transparent (a chroma key is exact for a two-color image; that is
   why remove-bg, which fills holes and grays the edge, is not used for flat icons).
   `--fill-holes F` exists for the rare glyph where a tiny enclosed hole is an artefact
   (`build_set.py` passes 0.00001, about 3 px), and `--post-fill-px 4` closes the 1-px pinholes that
   LANCZOS resampling leaves at acute concave corners.
6. **Stroke normaliser** `--min-stroke F` (e.g. 0.065): dilates the glyph with an octagonal footprint
   (corners stay chamfered) until the stroke measured on the output canvas reaches F; holes shrink by
   the same amount, so check `holes` in the report afterwards (a real hole that shrinks under ~20 px
   is closed with a per-icon `"post_fill_px": 16` override, as `teleoperation` does). It is the
   deterministic answer to the generator drawing connecting bars and outlines thinner than solid parts.
   `--close-px R` is the sibling tool for hairline gaps between parts that should touch (a grey closing
   with an octagonal footprint of radius R source px bridges gaps under 2R and leaves stroke width
   alone); it is only worth it when the gap is clearly smaller than every intended gap in the glyph.
7. Trim to the glyph and scale by `fit_fraction`: square-ish glyphs span `--fit 0.76` of the canvas
   (12 % padding); wide or tall glyphs are enlarged until their apparent size (square root of the
   bbox area) reaches `--area-min 0.60` of the canvas, capped at `--fit-max 0.88` (aspect 1.0 ->
   0.76, 0.55 -> 0.81, 0.50 -> 0.85, <= 0.46 -> 0.88), so a flat glyph does not look small and light
   in a row. Center by bbox (or `--center mass`). `badge.py` applies the same rule scaled to the
   badge diameter (`--glyph 0.58`, `--glyph-max 0.67`, `--area-min 0.458`).
8. Sheet guard: if the keyed image holds six or more glyphs separated by empty gutters wider than
   6 % of the canvas in both axes, it is an unsliced sheet; `chroma_key.py` warns (and `--strict`
   exits 3) instead of silently keying nine icons into one master.
9. `--report` prints bbox fraction, coverage, connected components, holes, `fit_used`,
   `dilated_src_px` and the estimated stroke width (2 x median distance-transform value on the
   skeleton) as a fraction of the canvas.

**Foreground-mask alternative.** For photographic or complex subjects (not flat icons), use a
foreground-mask cut-out tool such as `remove-bg` (macOS Vision; setup and quirks in
`references/ai-image-pipeline.md` section 8). Then run `chroma_key.py --keep-color` on a
green-background render only if the subject was generated on green; otherwise use the cut-out directly.

## 5. Recolor, badges, SVG

- `recolor.py MASK OUT --color navy|gold|white|ink|<hex>`; `--batch MASKS OUT --palette navy=003976,...`.
  Only the alpha is used, so there is never a green fringe and the color is exact.
- `badge.py MASK OUT --bg navy --fg white [--shape circle|rounded] [--glyph 0.58]`; `--batch ... --set atr`
  writes `-badge-navy` (white on navy, 11.4:1) and `-badge-gold` (navy on gold, 5.7:1). The badge is
  drawn at 4x and reduced with a box filter, so every opaque pixel stays exactly on the
  background/foreground blend line (LANCZOS would overshoot the rim by up to 20 levels).
- `trace.py MASK OUT.svg` renders the mask at 2x, traces it with vtracer in binary **polygon** mode
  (straight segments suit the chamfered geometry) and writes one `fill="currentColor"` path set with
  a default `color="#003976"`. `build_set.py` keeps an SVG only if its raster round-trip IoU against
  the master is >= 0.95 (the shipped set is 0.984-0.997).

## 6. QA checklist

1. `qa_sheets.py`, then look at `set-on-white.png`, `set-on-navy.png` (green fringe would show
   here), `set-on-gold.png`, `size-24px.png`, `size-32px.png`, `size-48px.png`, `size-64px.png`.
2. `weights.csv`: every outline glyph must sit in **0.06-0.10**; below that, add
   `"min_stroke": 0.065` to its `selection.json` entry (or regenerate with a firmer subject line);
   above 0.10 means a filled silhouette, which is only right for the `"fill": "solid"` pictograms.
   `make_readme.py` prints the gate failures.
3. Reject: rounded corners, gradients or shadows, stray letters/digits, broken or floating parts,
   a subject that needs > 3 elements to read, off-style outline/thin variants.
4. Minimum sizes are set per icon from the 24 px and 32 px sheets (`min_px` in `icons.json`, shown
   in the manifest), never assumed: compound glyphs (two figures, arrows between objects) usually
   need 32 px.
5. `build-report.json` carries every icon's numbers, source file and SVG IoU; badges must have no
   opaque pixel off the background/foreground line; masters must have no enclosed hole under 40 px.
6. In the ATR build repo, keep `build/qa/icons-verify/` (independent sheets and pixel checks written
   by the critic pass) passing: `verify_sheets.py`, `deep_checks.py`.
